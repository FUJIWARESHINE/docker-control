为什么需要设置仓库？

Understanding Repository Configuration

🌍

网络访问困境

原生 Docker Hub 在国内无法直接访问，虽然本系统内置了代理设置，但很多用户没有稳定的代理服务。 通过配置镜像源，可以让系统正常检查容器更新，无需依赖代理即可获取最新版本信息。

❓

为什么能拉取却不能检查更新？

镜像拉取和版本检查是两个不同的功能：

  • 镜像拉取：通过 Docker Registry API 的 Blob 接口下载镜像层文件
  • 版本检查：需要调用 Manifest API 查询镜像的 Digest 值来对比版本

许多镜像源为了节省带宽和成本，只开放了 Blob 下载接口（支持拉取），但关闭了 Manifest 查询接口（不支持版本检查）。 这就是为什么有些镜像源能拉取镜像，却无法用于检查更新的原因。

🎯

为什么推荐自建服务？

公共镜像源存在以下问题：

  • 接口限制：大部分镜像源虽然支持拉取，但没有开放 API 接口调用
  • 稳定性差：类似 docker.1ms.run 虽然支持调用，但服务不稳定且有收费趋势
  • 随时失效：公共服务可能因政策或成本原因随时关闭

自建检测服务是最稳定的解决方案：完全掌控、永不失效、比代理更稳定！ 只需一台能访问 Docker Hub 的 VPS，即可为自己和团队提供持久稳定的更新检测服务。

💡 建议：优先使用自建服务 > 公共服务 > 代理访问

1. 如何使用仓库设置

💡 什么是仓库设置？
仓库设置用于配置 Docker 镜像的检查地址、拉取代理和标签前缀，帮助您更快速地检查容器更新和拉取镜像。

三个配置项说明

🔍 检查地址

用于检查容器镜像是否有更新，支持拖动排序，优先使用排在前面的地址

🚀 镜像代理

用于加速镜像拉取，支持拖动排序，按顺序尝试拉取镜像

🏷️ 标签地址

用于标准化镜像名称，去除各种加速器域名前缀

操作步骤

1 添加配置

在对应的输入框中输入地址，点击"添加"按钮

示例： docker.1ms.run dockerproxy.com your-domain.com:2022
2 查看和管理

点击"列表"按钮，在弹出的窗口中可以：

  • 拖动排序：检查地址和镜像代理支持拖动调整优先级
  • 编辑：点击编辑按钮修改配置值
  • 删除：点击删除按钮移除不需要的配置
3 自动生效

配置保存后立即生效，无需重启容器。新添加的配置会自动放在第一位（最高优先级）。

✅ 使用建议
• 检查地址：至少添加 1-2 个可用地址
• 镜像代理：可选配置，用于加速镜像拉取
• 标签地址：通常使用默认配置即可

2. 在哪里找到可用地址

公共镜像代理服务

⚠️ 重要提示
由于政策原因，公共镜像代理服务可能随时失效。建议收藏多个备用地址，或考虑自建服务。

常用公共代理列表

服务地址 说明 状态
docker.1ms.run 常用选择 ⚙️ 不定期
dockerproxy.com 备用选择 ⚙️ 不定期
docker.m.daocloud.io DaoCloud 提供 ⚙️ 不定期

如何测试地址是否可用

# 方法1：使用 curl 测试 curl http://地址/v2/ # 方法2：测试查询镜像 curl http://地址/v2/nginx/manifests/latest # 如果返回 JSON 数据，说明地址可用

获取最新可用地址

您可以通过以下渠道获取最新的可用地址：

  • 🌐 GitHub：搜索 "docker mirror" 或 "docker registry proxy"
  • 📝 技术博客：关注 Docker 相关技术博客
  • 💬 技术社区：加入 Docker 技术交流群
  • 🔧 自建服务：参考下一章节自建镜像代理（推荐）
💡 推荐方案
如果您有自己的 VPS 服务器，强烈建议自建镜像代理服务。这样可以：
• 完全掌控服务可用性
• 避免公共服务失效的困扰
• 获得更稳定的访问速度
• 可以分享给团队使用

3. 自建镜像代理服务

⚠️ 前提条件
• 一台能访问Docker Hub的VPS服务器
• 已安装Docker和Docker Compose
• 服务器防火墙已开放2022端口

快速部署

1 运行容器
docker run -d \ --name hubhub \ --restart unless-stopped \ -p 2022:8080 \ -e HOST_KEY=yjnas \ -e IMAGES_PULL=false \ yjnas/hubhub
2 验证部署
# 测试服务是否正常 curl http://localhost:2022/ # 测试digest查询 curl http://localhost:2022/v2/nginx/manifests/latest
3 在 Diancup 中使用

部署完成后，在 Diancup 的仓库设置中添加你的代理地址：

your-server-ip:2022 或 docker.yourdomain.com
⚠️ 重要提示
输入地址时不要包含 http:// 或 https:// 前缀，只需输入域名和端口即可。
✅ 配置完成
Diancup 会自动使用你配置的地址进行镜像检查和拉取，新添加的地址会被优先使用。

4. 配置说明

环境变量

变量名 说明 默认值 必需
HOST_KEY 启动密钥，必须设置为 yjnas 无 ✅ 是
PORT 容器内部监听端口 8080 ❌ 否
IMAGES_PULL 是否允许镜像拉取（true/false） false ❌ 否

工作模式对比

功能 IMAGES_PULL=false IMAGES_PULL=true
Digest查询 ✅ 支持 ✅ 支持
Manifest获取 ✅ 支持 ✅ 支持
Blob下载 ❌ 禁止 ✅ 允许
镜像拉取 ❌ 禁止 ✅ 允许
适用场景 仅检测更新 完整镜像代理

5. 常见问题

Q1: 为什么添加的地址无法使用？

A: 请检查：

  • 地址格式是否正确（不要包含 http:// 或 https://）
  • 服务器是否可以访问该地址
  • 使用 curl 命令测试地址是否可用

Q2: 配置后多久生效？

A: 配置保存后立即生效，无需重启容器。

Q3: 可以添加多少个地址？

A: 没有数量限制，但建议：

  • 检查地址：2-5 个
  • 镜像代理：3-10 个
  • 标签地址：使用默认配置即可

Q4: 如何调整地址优先级？

A: 点击"列表"按钮，在弹出窗口中拖动调整顺序。排在前面的地址优先级更高。

Q5: 删除配置后会怎样？

A: 删除后该地址将不再被使用。如果删除了所有地址，相关功能可能无法正常工作。
